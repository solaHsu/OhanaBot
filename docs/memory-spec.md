# 记忆与成长规范

## 1. 分层与所有权

| 层 | 文件投影 | 保存内容 | 修改方式 |
| --- | --- | --- | --- |
| 灵魂 | `bot/memory/soul.md`（v1 冻结基线） | 名字、独立身份、原则、稳定性格 | 初始化导入；后续显式审阅版本差异 |
| 风格 | `bot/memory/style.md`（v1 冻结基线） | 分场景表达习惯与输出约束 | Growth 提案，验证后小幅更新 |
| 人物 | `conversations/people.md` | 按会话划分的人物事实、偏好、互动边界 | 有来源的增量更新 |
| 日简述 | `conversations/daily/YYYY-MM-DD.md` | 按会话分节的事件、约定与未决事项 | 每日任务幂等生成 |
| 工作记忆 | SQLite 中的近期事件 | 当前对话与待回复任务 | 自动淘汰，非永久记忆 |

SQLite 是运行记忆的权威来源，Markdown 是供阅读与审阅的版本化投影。初始人格文件通过显式导入建立数据库版本；运行时不直接读取被任意编辑的文件覆盖数据库。`people.md` 和日文件可包含多个会话，但 Context 必须检索结构化条目，不能整文件送入模型。

## 2. 条目结构

```json
{
  "id": "mem-001",
  "kind": "person_preference",
  "subject_id": "p001",
  "scope": "group:g001",
  "content": "偏好简短的技术说明",
  "source_kind": "live",
  "source_ids": ["event-001"],
  "evidence_type": "explicit_statement",
  "confidence": 0.9,
  "observed_at": "2026-09-01T10:00:00Z",
  "updated_at": "2026-09-01T10:00:00Z",
  "expires_at": "2026-11-30T10:00:00Z",
  "status": "active",
  "version": 1,
  "supersedes": null
}
```

`kind` 首版支持 `person_fact`、`person_preference`、`episode`、`commitment`、`reflection`、`style_candidate`。`scope` 只能是具体会话或经过审核的 `global` 人格/风格知识；人物事实不能自动提升为全局。

`source_kind` 区分 `live`、`historical_reference` 与 `self_reflection`。事实记录必须引用实际接收事件或历史资料；反思标记为自身判断，不伪装成外部事实。置信度由证据规则给出：明确自述可为 0.9，反复一致观察最高 0.7，单次推测最高 0.4。低于 0.8 的人物条目不自动作为事实注入，可作为待确认候选。

## 3. 固化流程

单轮回复的记忆候选先校验来源是否存在、是否在当前会话、是否已撤回及是否包含隐私。未经发送确认的模型草稿不能成为 Ohana 发言事实。用户陈述可以从接收事件独立固化，不要求机器人回复成功。

每日在业务时区 03:00 总结上一自然日，按 `(日期, 会话, 输入水位, 摘要版本)` 幂等执行。仅引用允许保留的事件；覆盖无事发生、失败发送、待履行约定等状态，不能把发送尝试总结为已完成行动。迟到事件使对应日期生成新版本，替代旧摘要，不能重复叠加。

同一主体与属性出现新自述时建立新版本并保留替代关系；互相矛盾、玩笑或他人转述保留为候选，不覆盖已确认事实。历史成员风格观察不能直接生成在线人物关系。

## 4. 成长机制

每周生成一次成长提案，至少引用 3 个来自不同会话片段的有效证据，包含当前规则、建议变化、支持证据、反例和预期影响。初版自动成长仅允许调整白名单风格参数，如句长偏好、语气词频率、标点习惯；每轮最多修改一个参数，数值变化不超过配置量程的 10%。

固定身份、原则、数据权限、预算、平台配置及隐私规则不属于可自动修改项。性格与观点的显著变更只生成提案，需审阅后显式启用。遭遇挑衅、密集重复消息或单一用户持续灌输，不自动改变稳定人格。

风格候选必须通过固定回放集：身份一致、无隐私泄漏、无越权引用、输出长度和静默规则合格。通过后事务提交新版本，保留父版本及证据；失败则维持旧版本。新版本行为异常时通过本地管理入口回滚，之后的生成记录使用恢复后的版本号。

## 5. 存储约定

SQLite 最少包含 `events`、`jobs`、`outbox`、`memories`、`memory_sources`、`memory_versions`、`growth_proposals`、`deletion_tombstones`、`usage_ledger`。事件与任务同事务；记忆、来源关联和版本同事务。outbox 的任务 ID 唯一，发送限额预留计入 usage，失败释放，unknown 保留直到核对。

Markdown 快照由已提交版本生成到临时文件再原子替换，附版本号与生成水位。中途崩溃可从数据库重新导出；禁止先覆盖快照再写数据库。备份以 SQLite 一致性备份接口生成，不能在写入期间只复制主数据库文件而遗漏 WAL。

## 6. 保留与删除

默认工作事件正文保留 30 天，日简述保留 180 天，人物事实 90 天到期后须有新证据才延续；灵魂和已审阅风格长期保留。来源正文过期后可保留匿名来源 ID 与时间供审计，不能声称仍可还原证据。去重键和删除墓碑不保存正文，长期保留以防重放。

删除按人物、会话或来源执行，覆盖事件正文、画像、摘要、例句、检索索引、分析样本及成长证据。混合来源摘要重新生成；无法安全分离的条目直接失效。受影响的历史版本也需清除敏感正文，回滚不能恢复已删除内容。

原始 `content/` 不由日常引擎修改。若要求完整擦除，必须纳入离线原始文件、备份和身份映射的受控清理；完成前只能报告运行记忆已删除。墓碑阻止下次导入重建已删除条目。备份默认保留 7 天，恢复后先应用删除清单，再开放检索与发送。
