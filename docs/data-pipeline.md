# 资料处理与人格初始化

## 1. 输入契约

聊天 JSON 顶层包含 `metadata`、`chatInfo`、`statistics`、`messages`、`exportOptions`。消息读取 `id`、`seq`、`timestamp`、`time`、`sender`、`type`、`content`、`recalled`、`system`。`content` 内包含 `text`、`elements`、`resources` 和 `mentions`。

这是 QQChatExporter 格式，与 OneBot 在线事件格式不同，必须分别解析后归一化。消息 ID、QQ 号和 UID 均作为字符串保存，禁止经浮点数转换。历史 `timestamp` 为毫秒，OneBot `time` 为秒；最终统一 UTC ISO 8601。两种时间字段冲突时隔离记录并报告。

博客以 YAML 解析器读取 front matter，以 Markdown 结构提取标题、段落、代码、引用和图片引用。`draft: true` 的文章进入独立草稿分区，默认不进入模型上下文；仅有 TODO 或占位符的正文排除。代码与公式保留为知识材料，不混入聊天口头禅统计。缺失图片只登记引用，不推断内容或下载资源。

## 2. 归一化记录

所有处理产物包含 `schema_version`。聊天 JSONL 的单条示例：

```json
{
  "schema_version": 1,
  "record_id": "src-a:msg-001",
  "source_id": "src-a",
  "source_kind": "chat_export",
  "message_id": "msg-001",
  "conversation_id": "group:g001",
  "person_id": "p001",
  "timestamp": "2026-09-01T10:00:00Z",
  "text": "这个思路可以再想想",
  "segments": [{"type": "text", "text": "这个思路可以再想想"}],
  "reply_to": null,
  "flags": [],
  "eligible_for_style": true,
  "visibility": "source_only"
}
```

`source_id` 来自本地来源清单；`record_id` 表示来源定位，跨导出重复另外以 `(平台, 原始会话ID, 消息ID)` 识别。身份映射使用本地随机别名表，原始标识不写入公开文档。成员 UID 与 UIN 只有在结构字段明确对应时才合并，昵称变更不创建新人；不能确认的映射保留为独立身份。

博客记录采用同一公共字段，另有 `title`、`published_at`、`draft`、`section_path`、`content_kind`、`author_id`。作者未配置时为未知，不自动关联导出账号。

## 3. 处理顺序

1. 枚举输入并计算 SHA-256，登记导出器版本、文件大小和处理配置摘要。原始文件只读。
2. 解析并校验结构；坏记录隔离到本地错误清单。严重结构错误使本轮失败，不能悄悄生成空语料。
3. 映射来源、会话与人物标识；按会话、时间、消息序号稳定排序。
4. 去除重复导出中的同一消息；正常复读保留用于互动统计，不仅凭文本去重。
5. 排除系统与已撤回消息。只含媒体的消息保留类型和计数，不将文件名或链接当作语言样本。
6. 解析文本、表情、提及和回复关系。回复中的引用不计入当前作者风格；缺失引用使用未知标记。
7. 执行隐私替换，移除资源 URL、鉴权参数及本地路径；隔离高风险内容。脱敏后再落地供模型阅读的材料。
8. 生成语料、统计、抽样候选和 manifest，以临时目录完整生成后切换，避免中途覆盖有效产物。

不得把“短”直接判为无意义：单字回应、问号、语气词可反映互动风格。纯空白排除；纯链接与机器通知分类；相邻短消息可以在抽样时组成会话片段，仍保留原始消息边界。

## 4. 统计与抽样

`stats_report.md` 分别报告原始、重复、系统、撤回、无有效文本、隐私隔离及最终可用数量；排除类别按流水线顺序互斥，数量可核对。另报告解析失败、身份缺失、时间冲突及媒体占比。

有效语料按匿名成员统计消息长度分布、活跃时段、标点与表情习惯、常见词和短语。互动关系优先用显式回复与提及；时间相邻仅标记为弱关联，不能直接推断亲密程度。中文分词词典与停用词版本写入 manifest。

转发与模板内容单独标记：跨成员归一化后重复的长文本（≥40 字）标为 `likely_forwarded`，同一成员重复三次以上的长文本标为 `repeated_template`，同一成员跨群同文标为 `cross_posted`，新闻/摘要模板标为 `ai_digest`；命中记录的 `eligible_for_style` 置为 false，保留在语料中仅作兴趣参考，不参与语言风格统计。抽样可用配置 `member_overrides` 对个别成员扩容。

`02_sample.py` 使用固定随机种子，按成员、月份、长短消息、回复场景分层，限制高活跃成员占比。样本携带前后各至多 3 条同会话消息，显式引用可额外补入但总数有上限；上下文仍需同样脱敏。默认每个成员最多 200 个中心样本，不足时全取并标记覆盖缺口。

按会话片段分开分析集与评估集，并对最近时间段留出测试材料。不能将同一中心消息的邻近上下文分配到不同集合。manifest 保存种子、记录 ID 清单、配置版本、脚本版本和输出摘要。

## 5. 从资料到人格

先生成成员风格观察与博客写作观察，再合成 Ohana 的独立人格候选。所有特征记录证据来源、支持与反例、置信度、适用场景，不用词频直接推断心理或价值观。

初始化配置显式指定参考成员与权重；未指定时只输出逐成员观察，不合成为某个人的数字替身。群聊风格与长文风格分开，原则由项目所有者定义并结合证据讨论，不从群聊中自动提炼成不可变规则。

候选至少覆盖身份说明、核心原则、交流偏好、幽默边界、分歧处理、知识边界和若干脱敏例句。禁止将他人的旅行、学校、工作、关系等事实变成 Ohana 的个人记忆。历史知识记录标记 `source_kind=historical_reference`。

流程为：离线分析 → 候选文档 → 确认基线 → 导入运行记忆。人类初始化确认不属于日常回复审批；运行期按已配置边界自动交流。

## 6. 脚本接口

```text
python scripts/01_preprocess.py --input content --output analysis --config config/analysis.local.yaml
python scripts/02_sample.py --input analysis/corpus --output analysis/samples --seed 42
```

预处理默认纯本地，不调用模型。分析模型步骤单独执行并遵守出站策略。重复运行同一输入与配置应得到相同记录集合、统计及样本；运行时间等非确定性字段不计入结果摘要。
