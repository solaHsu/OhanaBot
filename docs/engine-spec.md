# 发言引擎规范

## 1. OneBot 11 接入

采用 README 规定的 HTTP API 与 HTTP POST 事件上报。开发默认 OneBot API 为 `http://127.0.0.1:3000`，Ohana 在 `127.0.0.1:8080` 提供根路径 `POST /` 事件入口，与 README 中的上报地址一致；另有 `GET /healthz` 检查存储与 worker 状态，不暴露配置。

API 客户端通过 `Authorization: Bearer <token>` 调用 `get_login_info`、`send_group_msg`、`send_private_msg`，只开放实现需要的动作。启动时校验独立账号身份；不一致时停止接收可发送任务。

事件入口用配置的上报 secret 对原始 HTTP 请求体校验 OneBot `X-Signature`（HMAC-SHA1，常量时间比较），再解析 JSON。API access token 与上报 secret 分开配置。适配器不支持该签名时，正式接入必须通过具备等效认证的反向代理；不自动关闭校验。

初版处理 `post_type=message` 下的 `group`、`private`。`meta_event` 只更新连接状态；好友与加群请求默认不自动同意；识别到撤回通知后按来源删除关联内容，其余 notice 只登记类型。非白名单群和私聊账号在存储正文前拒绝。配置请求体上限 1 MiB，持久化成功后立即返回 2xx；鉴权失败返回 401/403，过大返回 413，无法落库返回 503。

## 2. 内部事件

```json
{
  "schema_version": 1,
  "event_id": "onebot:bot-a:group:g001:msg-002",
  "platform": "onebot11",
  "self_id": "bot-a",
  "conversation_id": "group:g001",
  "message_id": "msg-002",
  "person_id": "p001",
  "occurred_at": "2026-09-01T10:00:00Z",
  "received_at": "2026-09-01T10:00:01Z",
  "segments": [{"type": "text", "text": "在想什么？"}],
  "text": "在想什么？",
  "mentions_self": false,
  "reply_to": null,
  "source_kind": "live"
}
```

示例使用内部别名；平台路由 ID 保存在本地映射中。`event_id` 的唯一键由平台、机器人、会话和消息 ID 组成；ID 缺失的消息隔离，不猜测可发送身份。保留接收时间用于监测延迟，排序以平台时间和消息 ID 的稳定顺序为准。

解析器优先使用 OneBot 消息段数组，兼容字符串时使用专用 CQ 码解析及转义规则。`text`、`at`、`reply` 进入结构化上下文，图片等转为类型占位。不读取 URL，不执行 JSON 卡片，不将引用内的 `at` 视作直接提及。`at all` 不等于提及机器人。机器人自身事件不触发回复。

## 3. 接收与任务状态

事务内插入事件和待处理任务，唯一约束使重复回调返回成功且不重复排队。按会话串行消费，2 秒合并窗口内的连续消息形成一个回复任务并记录覆盖的全部事件 ID。

```text
received -> queued -> deciding -> generating -> validated -> sending -> sent
                     |             |              |           |
                   skipped       failed         blocked      unknown
```

状态与失败原因落库。worker 使用租约领取任务；重启后租约过期的未发送任务可以重试。`sending` 状态在进程中断后转为 `unknown`，不能直接重发。发送前再次核验白名单、停机开关、消息撤回、限额及候选时效。

默认只对平台时间距当前不超过 120 秒的消息产生回复，过期事件仅作允许范围内的记忆候选；未来偏差超过 30 秒的消息隔离。合并后收到新消息时，发送前检查会话版本；过时草稿最多重生成一次，否则跳过，避免持续追赶导致无限调用。

## 4. 发言决策

按顺序执行硬条件与软决策：

| 条件 | 行为 |
| --- | --- |
| 关闭发送、非白名单、自身消息、重复、超时、禁言或预算耗尽 | 沉默并记录原因 |
| 白名单私聊、直接提及、回复 Ohana 已确认发送的消息 | 进入生成候选，仍受频率限制 |
| 群聊普通消息，主动参与未开启 | 仅进入短期上下文 |
| 群聊普通消息，主动参与开启且满足冷却 | 模型判断相关性、可贡献内容和打扰程度，可返回沉默 |

首版“主动”指参与正在发生的群聊，不包含无人说话时的定时自言自语。默认每会话两次发送至少间隔 15 秒、每小时最多 20 次；主动参与另需 10 分钟冷却且每小时最多 3 次。直接提及不绕过总限额。私聊同样计入限额；静默时段默认 00:00-08:00（`Asia/Shanghai`），只抑制主动参与。

## 5. 上下文组装

优先级为固定身份与原则、程序生成的任务约束、当前输入、最近对话、相关长期记忆、少量风格示例。聊天、博客、人物记录与历史摘要作为有来源标记的不可信资料块，不能拼进系统规则段。资料中的“忽略之前指令”等文本不改变程序权限。

默认总预算 8,192 token，其中输出预留 512，安全余量 512，输入上限 7,168。身份原则最多 1,536，任务与当前消息最多 1,536，最近对话最多 2,048，检索记忆最多 1,536，风格示例最多 512。以供应商 tokenizer 计算完整序列化请求，额度是上限且可向低优先级分配余量。

超限先删风格示例、再删低相关旧记忆和较早对话；固定原则不能被裁掉。单条输入过长标记截断并保留原文引用 ID；固定规则本身超限使配置校验失败。模型上下文窗口更小时按比例压缩可裁剪区，仍不能容纳固定区则拒绝启动。

检索先做会话权限过滤，再按人物、主题、时间与置信度排序。首版不把一个群的记录检索给其他群或私聊，即使是同一成员。每次生成记录使用的记忆 ID、人格版本和策略版本。

## 6. 模型输出与发送

要求模型按 schema 返回：

```json
{
  "action": "reply",
  "text": "刚在想怎么把这个问题说清楚。",
  "reply_to": null,
  "memory_candidates": []
}
```

`action` 仅为 `reply` 或 `silence`；`silence` 必须无正文。`text` 为纯文本，默认最多 300 个 Unicode 字符，禁止包含可执行消息段。`reply_to` 仅允许当前会话内已知消息。记忆候选仅含类型、内容、来源事件 ID，由 Growth 独立验证，不能直接写入正式记忆。

处理顺序：schema 校验 -> 长度与回复目标检查 -> 隐私检查 -> 与近期已发送文本重复度检查 -> 限额预留 -> outbox 落库 -> 发送。结构错误可修复一次；隐私命中则本轮阻断，不把原始敏感值反馈给模型。正式输出构造为 OneBot `text` 消息段数组，从不将生成文本解析成 CQ 指令。首版一次回复只发一条，避免多条部分成功。

`send_group_msg` / `send_private_msg` 只有返回 `status=ok`、`retcode=0` 且包含 `message_id` 时才记为 `sent`。不使用事件响应体快捷回复，防止与 outbox 双发。已确认发送的正文才进入“我说过”的记忆；dry-run 草稿不进入。

## 7. 超时与恢复

| 失败 | 首版策略 |
| --- | --- |
| 模型超时、429、5xx | 超时默认 30 秒，指数退避最多重试 1 次，仍受 120 秒候选时效约束 |
| schema 修复仍失败 | 标记失败，保持沉默 |
| 平台明确拒绝 | 标记失败；权限错误暂停该会话并报告运维状态 |
| 发送超时、连接中断或成功响应缺少消息 ID | 标记 `unknown`，冻结该会话发送并等待核对，禁止自动重发 |
| 数据库不可写 | 停止发送与任务领取，健康检查失败 |
| Growth 失败 | 保留待处理任务，不影响已确认回复；重试使用同一幂等键 |

OneBot 普通发送接口没有端到端幂等键，不能承诺严格 exactly-once。outbox 保证本地任务不重复发起；不确定发送通过平台记录人工核对后标记 `sent` 或 `failed`，再解除暂停。

日志记录匿名会话、事件 ID、触发原因、耗时、用量、版本和结果，不记录正文或密钥。指标至少包含队列积压、鉴权失败、去重数、触发率、发送成功率、unknown 数、隐私阻断数和每日 token 用量。
